3. 「生活 → 遊戲 → 生活」的核心循環

玩家承諾：我替自己做了一件有意義的事，回來後親手把一角世界變得更像我。

每 5–30 秒重複的動作：選一個位置／路線 → 預覽 → 放置或引導 → 看魚／植物反應。每 1–5 分鐘完成一次可說出結果的小目標，例如讓魚穿過新水道、拍到牠從遮蔭處游出的行為、完成一段岸邊。做得更好的玩家能看懂空間條件，搭出不同可行方案，而不是點得更快。

玩法契約：玩家在有限棲地格和互相影響的水流／遮蔭條件下，配置植物與石頭，讓選定動物出現一種行為；成功保存棲地、發現或個體成長，失敗顯示哪段路被擋或哪個條件缺少，免費調整再試。壓力來自空間取捨與解題，不來自動物生死、倒數催促或資源歸零。

完整鏈條：

  1. 使用者選「今天我想推進的一步」，可來自任何已接通模組，也可以是自行選定的休息。
  2. OS 原本的功能保存完成；伺服器核對來源、帳戶、發生次數與限額。
  3. 給一張具體的建設機會卡：例如「可加一組岸邊植物／一段導流石／一個觀察角」。卡顯示來源與為何取得，不顯示人生價值分數。
  4. 玩家回到世界，選一個配方並親手放置、測試與調整。保存後，這件物件成為永久所有物，可免費移位。
  5. 世界出現持久變化：魚的路徑變長、蘆葦旁出現棲息點、圖鑑留下發現，並可追溯「來自我選的那一步」。
  6. Buddy 在自然結束點問「要不要為這個專案選下一個小步？」使用者可以打開原模組、另選方向，或就此結束。不自動替使用者新增待辦。

生活回饋不是另一種無限 XP

首版不設等級條、通用金幣、戰力、稀有度排行榜或交易。建設機會卡是「新增一件永久物件的授權」，必須由玩家選配方與擺放；單純領卡不算世界改變。圖鑑與行為發現靠遊玩，生活卡不能跳過棲地理解。

每天推薦 1 件生活重點，可自願加 1 件；任何連續 24 小時最多發 2 張、168 小時最多 6 張，以伺服器發放時間計算。這是避免任務量越大回饋越多的初始上限，不是要使用者拿滿的配額。介面不放「尚差 4 次」。超過上限仍照常保存生活紀錄、可看完成回饋，但不囤下大量待領卡；已發卡永久保留、不過期。離線多日集中補傳，不繞過發放上限。

同時最多保留兩個進行中的 intention；完成、跳過或替換後才選下一個。伺服器首次結算若已達上限，記錄 acknowledged_without_grant，該次證據之後不會因重試變成待領卡；畫面說明「已記下這一步，今天可以繼續佈置已有物件」。網路尚未完成核對的 pending 與已結算達上限是不同狀態。這些規則應先以訪談確認是否易懂，不能讓使用者完成後才發現一個從未說明的限制。

卡依來源預選相稱配方：專案一步建議導流石，感謝／反思建議植物或觀察角，學習運用建議觀察工具。任何卡都可免費改選目前開放的等價配方，所以只用 Tasks 的人也能取得蘆葦；不強迫寫日記來養某種魚。物件名稱與來源故事保留情境，功能不按行動「高低貴賤」排序。

基本漫遊、重新配置已有物件、引導／觀察魚群、拍攝圖鑑、重玩空間題不耗卡，也不消耗行動體力。沒有新生活資料的一天，仍有完整可玩內容。

4. 活水魚塘：第一個值得玩的系統

4.1 解鎖與第一分鐘

新玩家走到既有池塘，Buddy 給一個免費 starter kit：兩株岸草、一塊導流石、一片浮葉；再給兩尾入門魚。玩家先選「靠岸的觀察灣」或「小小水道」，立即放置與測試，不必先補三天生活紀錄才看到魚。原有 V2 玩家可直接進入教學或跳過，已有 stamp 給一個紀念銘牌，不換算成魚塘購買力。

第一個生活行動完成後，得到第一件自己選的新增物件，讓世界與生活開始相連。首個行為觀察應能在 3 分鐘內完成；育成與繁殖不是入場門檻。

4.2 操作：3D 世界加可讀的配置模式

池塘以 3×4 個邏輯位置作首版配置面；世界內呈現自然曲線，格子只在配置模式出現。固定地形標示淺水／深水與入口／出口，玩家不能任意填平整個池。點物件→點位置→旋轉→確認，桌面可拖放；手機與鍵盤有完整點選替代，無須精準拖小魚。

四類物件明確限定為岸草、浮葉、導流石、棲息／觀察設施。物件可免費收回工具盤再放置，收起不刪除所有權與來源足跡；配置格限制同時展示數量，而非總收藏數。新卡可以保留到想建造時才使用，不設囤卡警告。首版內容有限，若玩家已試完主要配置，應如實提供自由佈置與觀察，不以無限發重複物件冒充長期內容；這正是 P2 是否值得投入的驗證點。

三個可見條件：通道、遮蔭、岸邊棲地。它們是易懂的遊戲生態規則，不是飼養真魚的水質模型。首版不模擬酸鹼值、氨氮、真實物種相容性或食物鏈死亡。

玩家操作真正的選擇／技能即時看得見的回饋持久結果
放／轉導流石保留水道，或分出緩流灣；石頭佔位置先預覽流向；被擋的路用虛線指出，不能只用紅綠色保存後的路線影響巡游魚、可建立不同方案
安排岸草／浮葉留出連續開水面，同時提供遮蔭；不是放越多越好遮蔭輪廓與可用空水位置變化；魚游向適合區域解鎖觀察行為及物種條件
以水紋引導魚群按三個不重疊水面位置，預測魚會繞障礙前往哪裡漣漪擴散，魚轉向、停留或繞路首次完成新的路線型態留下觀察卡；重玩不量產資源
靜觀與拍攝從岸邊選角度，辨認一次行為；不靠手速魚靠近／躲進葉影；文字標示目前可觀察的特徵物種／行為記錄，拍攝可免費重做
培育與配對（後續）選父母外觀特性和育幼區，而非買更高數值預覽可能的兩種結果與必要條件新個體有永久 ID、名字、來源與花紋；非賭稀有抽卡

「投餵」改為可選的呼喚／靠近互動，不設會減少的飢餓條；它不代表不回來魚就餓。需要聲音的操作都有文字與視覺結果，音量零仍可通關。

4.3 規則與差異：三個入門動物

虛構遊戲動物出現／活動條件觀察挑戰擴充意義
晨光魚初始贈送；至少 3 個連接的開水位置可展示巡游用水紋引導牠走過一條有轉彎的通道教移動與路徑，不用金錢／XP
葉影螺兩個相鄰岸草位置，旁邊有一個開水位置；測試一次棲地找出牠從石邊走向葉下的路徑教相鄰配置；不能整池堆同一物件

條件達成後，可在當次 60–90 秒的「看看誰會來」觀察中確定遇見，沒有隨機抽不到的核心物種。這個等待含可做的路徑觀察，不必盯著倒數；選擇離開後，事件會等下次回來呈現，不失效。第一個晨光魚觀察即時可玩，不必等這段時間。

首版格子限制要支援至少兩個不同有效配置。大量同款岸草會佔去通道與水面，造成「這種行為尚未出現」而非扣幸福值。編輯不合適時，魚仍安全地留在既有灣；重新排列只暫停尚未完成的條件，不取消圖鑑、已成熟階段或已開放區域。每種動物只首次發現一次；不同裝置不能各領一次。

4.4 生長、繁殖與每次回訪的新細節

首版晨光魚只有幼魚／成魚兩階段。已完成一種行為觀察且首次保存合適棲地後，伺服器記錄成長里程碑；最多在 8 小時後具備成魚外觀資格。玩家隨時可晚點回來，沒有錯過窗口；離線不需模擬每秒，也不多次累加。第一次成長不要求下一個生活行動，避免動物被綁成生活考核工具。

後續繁殖版：兩個已成熟個體＋一個保存過條件合格的育幼區＋玩家明確選擇配對，產生一個 brood ID；同一配對命令重試只產生同一 brood。顯示下一個外觀特性的可達路徑，例如暖色／點斑，不設付費抽取、稀有率倍增或無限刷子代。子代可觀察後收進收藏水灣；前景展示上限是效能／空間限制，其他個體不死亡、不被售出。幼魚與 parent metadata 在伺服器保存，擺尾由本機畫面處理。

P2 可實作的配對例子：先只做「底色」和「花紋」兩個離散特性。晨光色・素面與霧青色・點斑配對時，玩家選想保留的父母底色之一，再選父母花紋之一；四個可達組合直接預覽，沒有隱藏機率。育幼灣需兩格相鄰岸草、一片相鄰浮葉，以及至少三格連通水面。條件不合時顯示缺項，免費重排；成立後先保存棲地與配對選擇，再按「開始培育」。每帳戶同時一個 brood，暫定 8 小時後可迎接一尾；時間只產生一次資格，玩家多久後回來都相同。確認後給子代永久 ID，名字可跳過，收藏保留父母與所選特性。啟動後改配置不撤銷 brood，未開始的下一次仍重新核對條件。

第一個育幼區由生活建設機會建立；之後用既有區域配對不再要求額外生活卡，避免把每尾幼魚變成待辦獎品。養成深度來自有計畫的組合、個體記憶與配置，不來自稀有率。首版收藏章節只列有限、可達的組合，完成後可繼續自由配對或換區；不宣稱能提供無限新鮮感。以上為 P2 設計假設，repo 尚未有個體／brood 實作。

每次回訪由已有世界狀態選出最多一件尚未看過的變化：幼魚輪廓變大、魚第一次走到浮葉下、螺出現在新岸草旁、某隻魚與 Buddy 打招呼。沒有新變化時說「今天可以試另一種水道」，不能捏造「新魚已到」。日夜改變光色與聲景；核心物種不限制現實時段。季節內容未來可增加，但用收藏章節提供常駐重訪入口。

4.5 完整例子：專案一步長成一片岸邊

小晴選自己的「作品集」專案下一步：完成一段自我介紹初稿。她不是因為專案很重要而獲較高分，而是自行選定這一步並把完成保存到 Tasks。

回饋卡寫：「你完成了自己選的初稿，可以替池塘加一件設施。」她選岸草，進入池塘後發現把它放在出口會縮窄魚道；預覽直接顯示缺口。她把岸草移到原有岸草旁，形成葉影螺的棲地。晨光魚沿保留的水道游過，螺的輪廓在石邊出現；觀察後保存圖鑑。該岸草能查看來源「作品集的一小步」，但公開截圖預設不展示任務標題。

Buddy 說：「你留下的這片岸邊，讓葉影螺有了位置。要替作品集選下一個小步，還是再看一會魚？」她可結束遊戲。之後專案暫停或改名，岸草、螺與圖鑑都保留；只更新未完成的下一步。

5. 每日自選小任務：生活行動 → 回饋 → 世界變化 → 解鎖

首頁只呈現一個已選重點，另有「換一件／今天跳過／縮小一步」。下面是可供選擇的任務庫，不是一口氣塞給使用者的清單。推薦按使用者的方向、已啟用模組、最近選擇與自行設定的可用時間過濾；標記 urgent 不會自動變成遊戲強制任務。

所有列共用前述發放上限。每張卡選一個配方、只生成一件新物件；不是同時送完整設施組。功能等價的替換始終可用，來源敘事只是預設推薦。下列新事件名稱均為待實作規格。

表中的路標、座位、小花與觀察牌是四類物件的後續外觀／功能方向；P1 只交付各類的基本款，不代表首版會同時製作表內所有配方。尚未發布的配方不出現在可選清單。

推薦與完成 UX

接入順序明確分開：P1 的候選來源是 Task、Habit occurrence、Gratitude 與明示自報休息。Projects／Goals／Career 先作使用者選定的方向，完成依據仍回到同一具體 Task；Journal、Knowledge 應用、Planner 整理確認是 P2 的 adapter 工作。上表的「明確子步」不代表目前已有獨立 subtask 授獎 API；P1 可確認同一 Task 的部分推進，但之後全部完成不再給第二張。

提出 2–3 個合理候選，預選項也需使用者接受。已在 OS 完成但沒預先選的今日行動，可以由使用者指定為今天重點；只接受本次生活日內的新證據或既有明確未結算 intention，不掃描舊歷史補發一箱卡。未啟用的模組不出題；伺服器驗證 unavailable 時，保留生活紀錄、顯示待確認，允許改選自報行動。

回饋遵循三種狀態：來源尚在保存→「先記下，連線後確認」；伺服器發卡→「這次行動能添一片岸邊」；世界 command 保存→「岸邊已安置好」。樂音／小圖示可即時播放，但正式物件與「已保存」不能在 server 成功前假裝完成。

同一行動、拆分與新的下一步

「一次機會」的身份是使用者選定的成果，不是每次勾選或每張資料列。這裡需要兩個不同層次：目前候選的 明確關聯證據 把 Task／Habit／Gratitude 的同一次行動綁到一個 intention；未來的 lineage／step occurrence 處理同一成果的複製、拆分與真正後續投入。repo 尚未有完整通用 lineage，不能在防刷說明中假設它已存在。

應用程式內邀請由前景檢查世界事件觸發，不需新的外部通知服務。背景推播另需 subscription／取消訂閱管理、server scheduler、delivery／重試／過期控制、平台權限與可觀測性；現有 timer notification 不足以完成。首版不做。若之後批准加入，訊息只發一般生態事件，不帶私密 task／日記標題，並仍套用同一份跨裝置頻率預算。

8. 第 1 天、第 7 天、第 30 天

第 1 天：一位只有 Tasks 的新玩家選「整理要寄出的草稿」。也可以先不選、直接走進花園。免費 kit 讓她完成第一次有轉彎的魚道，第一次理解「位置會影響行為」。做完草稿後，她拿到一件可改選的設施，放到自己選的岸邊。她離開時有兩尾魚、一個自己造成的變化、一個清楚的下一步。目標是一次 3–5 分鐘遊玩；生活行動需要多久由她決定。

第 7 天：她只在四天帶回生活成果，其中一天是休息，沒有連續 streak 要補。四張卡已變成不同物件；她試過兩種有效棲地，見到三種動物，選擇打開下游濕地。週工程「安靜岸邊」還差觀察，不因星期結束而歸零。某天沒有新卡，她只是重新布置和看魚，也是一個合理的遊戲 session。

這段是後續內容已發布時的理想故事。若當時只有 P1，D7 就以第二種魚路、三物種收藏與可保留的角落計畫結束；不顯示可進入但尚未製作的濕地，也不要求先消耗建材等待開發。

第 30 天：原先作品集專案暫停，她改把方向放在健康作息；以前的岸邊不受影響。她的世界有已建立的魚塘、幾隻有名字的魚、下游可探索的路線和一份生活足跡。她可能只玩魚塘，也可能達到林地條件；內容發布後再自行選擇下一區。這是完整方向的體驗故事，不承諾第一個魚塘版本在第 30 天已交付所有區域。

三個故事都不要求每日登入、使用所有模組、達成規定工時或說出正向情緒。

9. 可安全實作的系統架構

以下是建議的邏輯模型與 API 職責，不保證名稱與候選程式逐字相同，也不代表正式 API 已可用。部分模型已存在未發布候選 SQL，對照見 最新 repo 審查。沿用 Next.js／TypeScript／Supabase；不新增遊戲後端供應商，不先重構全站成 event-sourcing 系統。

9.1 三種事實，三個責任邊界

第一種是生活來源事實，例如 Tasks 的狀態轉換或 Gratitude 保存；第二種是授予使用者的機會；第三種是玩家在世界裡做的操作。它們不能混成一張「總 XP」表，也不能用瀏覽器 event 當三者共同的真相。

資料流：原 OS 寫入 → 最小來源 receipt → intention 配對與授權 transaction → 機會卡 → world command transaction → 保存世界變化 → Buddy 未讀事件。

9.2 來源如何被信任

先支援 Tasks、Habit Completion、Gratitude，以及顯式自報的休息；Journal 需先通過 schema／寫入驗收。對已支援來源，增加小而可測的 DB transition receipt：只有 task 進入 done、habit occurrence 進入 done、記錄初次保存等有效轉換才 append metadata。來源寫入與 receipt 在同一 transaction，重複保存沒有新事件；重新計算玩法、推播和 AI 不在這個 transaction 內。

receipt 僅為已啟用 Garden 且同意該 connector 的帳戶建立；未啟用者的原模組寫入維持原行為。停止連接後不再收新來源證據，已取得世界保留。為支援「今天完成後才選重點」，可暫存當日最小 receipt；未被 intention 使用的 receipt 按明確短期保留政策清理，不能藉此建立全站永久行為追蹤。

這個小 trigger／受控 mutation adapter 已有候選程式，但仍須盤點並驗收 bulk update、Planner、AI flow 等所有寫入入口。先在 isolated DB 測試再分模組開啟；任何 receipt 錯誤會影響原寫入，所以需監測失敗率並有停用該 connector／回滾新增 trigger 的方案。不能以「先寫 OS，再發一個易丟的前端 event」假裝有原子保證。

grant RPC 重新驗證 auth.uid、來源 ownership、有效 receipt、目前狀態／更正、intention 版本、canonical key 和發放上限。行動真實性仍屬自報；它驗證的是正確帳戶保存了正確記錄，不讀內容評價投入品質。只看 client 傳來的 completed_at 或 value 不夠。今天補選已完成行動，必須有 rollout 之後產生的當日 server receipt；缺 receipt 可選「我今天做過」自報，明示證據類型，不冒充歷史完成事件。

自報由受控 endpoint 產生 receipt，與已驗證保存的記錄同樣受 intention 和總額限制。Knowledge「已運用」、Planner「已整理」也是這一類明確確認事件；不是時間到就自動完成。未接入來源不提供靜默 backfill。

9.3 Command 與同步

提議 command：select_intention、confirm_life_action、claim_opportunity、place_object、move_object、record_observation、start_brood、mark_world_event_seen。每次帶 UUID command_id 和 expected revision；payload 的 user_id 不當寫入目標。

Server 先鎖該 user 的 world／grant budget row，以固定鎖順序執行：檢查重試結果→檢查來源與規則→新增 grant 或消耗既有 grant→更新物件／milestone→增加 revision→寫入 command 結果與 world_event→commit。回應在 commit 後遺失時，同 command_id 取回相同結果。金額／數量、機會消耗、物種條件、育成時間、區域解鎖、placement 格子與相鄰規則均由 server 驗證。

Client 只處理移動、魚群 steering、粒子、水紋、鏡頭與音符；可本地預覽放置，沒有 server confirmation 前標示「待同步」。不得讓 client 的「畫面已看見蜻蜓」直接鑄造永久物種。正式 observation command 需檢查既有棲地和允許的行為狀態；不需要把每幀輸入上傳當防作弊，也不聲稱能證明玩家真的用眼睛觀察。

同時兩裝置改同一格，第二個 stale revision 回 conflict＋新 state；保留使用者待放的 ghost 物件供重新選位，不用 last-write-wins 蓋掉第一個人的成果。獨立已確認發現可按唯一事實合併；放置／移動順序不可亂排。

離線：依 account ID 隔離 IndexedDB outbox（可從現有 localStorage queue 的模式遷移），保留 command_id、base_revision、schema_version、source refs。網路恢復後先刷新帳戶與 capabilities，再按依賴順序重送。來源刪除／身份變更／舊版本 command 不盲目重試；提供重選或保留設計草稿。已發卡不過期；尚未可核對的離線行動可在來源同步後確認，或改明示自報，不能用任意過去日期套利。

9.4 日期與時區

新生活推薦使用帳戶 IANA timezone，auto 初次採裝置 zone 後讓使用者確認；每個 intention／receipt 保存 zone_at_selection、server observed_at、life_window_id。生活日預設本地 04:00 分界以照顧晚睡，不要求真實 04:00 前回訪。安靜時段單獨計算，不等同生活日。

來源日期與生活推薦日分開。 現有 Habit occurrence 是原模組的 completion_date，不能被 Garden 的 04:00 分界重新命名；新候選會把原 Habits 所用的裝置日曆日期與 IANA zone 一起保存到 command，由伺服器以現在時間核對；舊 pending command 保留世界日曆相容規則。連接時固定原 occurrence 和來源 zone，晚間／跨午夜保存及離線重試都核對這個 key；Habit 的完成後選重點使用來源午夜，不套用 04:00 推薦分界。詳見 Habit 日期契約。資料庫 current_date、裝置 UTC 日期與來源日期未必相同，測試不能互相代用。Journal／Gratitude 的補記日期亦不直接等於授獎窗口；server observed_at 決定新證據何時被觀察，原日期只作使用者紀錄。

旅行／變更時區不改寫舊事件或重開已完成機會；當前 window 以原分界結束，下一個 window 才用新 zone。DST 23／25 小時日由 IANA 計算，不把固定毫秒當所有日。rolling 24h／168h grant 上限額外限制跨時區多領；變更時區不增加可領量。使用者能看到目前日期／zone 說明，但平常 HUD 不顯示這些技術欄位。

舊 V2 expedition 仍按 UTC 保存，不回頭重算 stamp，也不把同一天重新歸類再發一次。遷移後新的生活足跡按新 window 計算；舊歷史保留「原探險日」解釋。補記昨天的日記不自動創造昨天／今天兩次機會，receipt 和 canonical grant 決定唯一性。

9.5 安全、隱私與舊玩家相容

RLS owner-only read；獎勵／world mutation 不開 direct client INSERT／UPDATE，透過已審查的 RPC。private definer function 固定空 search_path，引用 fully qualified objects，限制 payload 長度、允許 command、版本、範圍及執行角色。RLS 只是隔離的一部分，仍需 unique keys 和交易來防止重領。Supabase 官方說明

V3 用 additive schema 與 per-user migration marker。舊植物、收藏、stamp、音量偏好及 Buddy 身分保留；stamp 只提供 once-per-account 紀念裝飾，未核實的 legacy chest／肥料不轉為新授權。新玩家和舊玩家都拿相同可玩的 starter kit。舊 pending V2 commands 仍走原 RPC；不能因舊 action regex 不識 V3 而清空所有 outbox。

切換 feature flag 回 V2 時仍保留 V3 world data；重新開啟只讀同一 migration marker，不再發 starter。新魚塘與舊植物的成長要有獨立 migration adapter，不修改歷史 action 的意思。

資料刪除時，移除 source refs／可辨識來源文字，長期物件只保留非敏感的來源類別與自訂外觀。帳戶刪除才隨帳戶清理世界。跨帳戶 cache／outbox 不能復用。設計與除錯 telemetry 不存日記、任務全文、Career 私人資料、精確位置或原始按鍵。

10. 美術、音效與跨裝置成本

延續當前淡 sage／lime、石灰白、柔木色、slate 文字、霧面石材與奶白玻璃 HUD。魚用可辨識的輪廓、克制花紋和柔和鰭片；避免高反射寫實水面吞掉魚影。第一版鏡頭不進入水下，靠岸近看與配置俯視有清楚切換。

主 HUD 只留「目前想觀察的事」、必要水面／棲地提示、pause／exit；卡片收在工具盤。手機配置時縮起 joystick，位置選擇用大格與確認鍵；返回探索後恢復原控制，不能同一手勢同時移動人物與挪動物件。長任務標題留在可打開的來源面板，不佔滿世界畫面。

音樂沿用 A Little More Green，76 BPM。池邊弱化上層旋律、加入稀疏水滴；放置成功用木／石輕響，觀察發現用現有音階的兩三音應答，Buddy 保留 G–A–D motif。最多約 8 個短 SFX 同時發聲，水紋聲有間隔與距離衰減，不為每尾魚建一個長駐 AudioNode。沿用整體開關與 music／effects／nature 三路，user gesture unlock，blur／pause／exit suspend。音樂不隨任務量變快、變大聲；靜音不影響遊戲判定。

全螢幕沿用 native API＋100dvh fallback，保留安全區、明顯退出、焦點還原和 Esc。控制目標至少約 44 CSS px，窄屏 320px 也能操作配置；橫直切換保存選中格子／草稿，pointercancel／lostcapture 不能讓人物一直走。顏色搭配文字／形狀雙重提示。

11. 分階段實作、依賴與驗收

P0：驗證與資料地基

先用原 V2 建立少量自願測試者 baseline，並做可切換兩種棲地解法的互動原型。確認玩家願意玩，再把來源 receipt／intention／grant／world command 的薄片串起來。優先接 Tasks、Habit Completion、Gratitude、自報休息；Journal、Planner、Knowledge 應用不阻擋首版。

依賴：現有登入／Supabase、最小 source adapters、per-user RLS、規則版本與 feature gate。盤點被不同 UI 直接更新的完成入口。若原模組寫入已不可靠，先修 connector，不能用 mock 宣稱連通。

驗收：同 source 重試、取消再完成、bulk done、刪除重建、habit date 重複、跨帳戶引用、兩裝置同時 claim、改時區與 DST、離線補傳均有具體規則測試；單次來源寫入與 receipt atomic；Garden 暫停上線不破壞 OS 核心資料。

P1：最小可玩「活水魚塘」

明確範圍：同一張現有地圖、一個 3×4 配置面、4 類可重排物件、晨光魚／葉影螺／藍翅蜻蜓、兩種有效棲地、一次幼魚成長、近看觀察、圖鑑、生活機會來源卡、實際帳戶 save/restore。Buddy 有歡迎／提示／一次成果解釋；前景內容邀請可選但不依賴背景推播。

首版不做魚類繁殖、基因組合、四區同時開放、自由地形雕刻、物品買賣、社交贈魚、其他玩家進入、背景推播或付費稀有度。先用受控且能解釋的三種物種證明迴圈。

驗收：5 分鐘內從生活來源完成到放置並保存一個世界物件；沒有生活資料也能用 starter 完成觀察；至少兩種配置產生不同可見路徑；失敗免費修正；A 裝置新增後 B 裝置恢復相同物件；未知回應不重複消耗；撤銷生活完成不沒收世界；手機、鍵盤、減少動態、靜音與 no-WebGL 路徑皆可取得同結果。

P2：長期魚塘與自選每週工程

加入成熟配對／育幼、個體花紋、收藏水灣、三段式自選工程、內容化 Buddy invitation；Journal 經相容性驗收後接入，Knowledge 加顯式應用記錄。每個物種增加一個新行為／棲地關係，不只是換色。

驗收：連續模擬 30 日／休息 30 日，沒有物種死亡、時間累積爆增或缺席債；配對去重、active-display cap、來源刪除隱私、拒絕提醒七日抑制、已發卡不過期均通過。玩家訪談能說出「哪個生活行動造成哪個變化」。

P3：先開濕地，再決定森林／溫室

濕地先做分流／連通的獨立動詞與新鏡頭尺度，不能複製魚塘刷三次。只有當池塘的享受度、理解度、跨裝置穩定度達標，才增加第二區。森林／溫室各自做一個 prototype 驗證後排期。背景推播是另外一個可拒絕的工程／產品決定。

以下是原始從零規劃的人力範圍；目前已經有部分候選程式，剩餘工期需按最新缺口重新估算。粗略投入估計：P0 約 1–2 週；P1 約 3–5 週；P2 約 2–4 週；每個新區域另估。假設 1 位熟悉 repo 的全端／Three.js 工程師，加部分美術與 QA 支援；這是人力規劃範圍，不是交付日期。若發現登入／來源寫入需修復，或要求額外 3D 資產，應重新估算，不以省略測試維持日期。

發布閘門

通過 pure rule tests、SQL／RLS／concurrency tests、production build，再執行真實輸入完整 playthrough、跨帳戶與跨裝置、physical mobile 10 分鐘、reduced motion／mute／fullscreen／fallback、資料遷移回滾。最後才以候選 migration 和 scoped patch 供實作階段批准發布。本階段沒有授權或執行這些變更。

對檔案的建議分工：保留 AdventureScene 渲染、GardenAdventure 路由／UI／狀態接線；新增純 garden/world-v3 rules、pond-system、生活 adapter 和 versioned repositories。避免繼續把所有新規則塞進現有大型 UI 元件；不因本功能改動全站架構。

12. 成效衡量：玩家的生活也要受益

北極星候選：「每週有一個自選生活成果，且親手留下一個持久世界變化的使用者比例」。分母是進入研究且啟用 Garden 的全部使用者，不只算已成功做完的人。這仍是行為代理，不等於人生真正變好，所以必須搭配玩家自述與負擔指標。

要回答的問題指標／定義防止誤讀
第一次是否好玩？進入→首個配置決策→有效觀察；Time to first meaningful interaction免費 starter 和有生活資料者分開；只載入頁面不是玩過
沒獎勵還想玩嗎？可自由配置／觀察的參與；自撰題「即使沒有新物件，我仍想再試一個配置」停留時間可能只是卡住；配合失敗／求助與觀察訪談
生活方向有推進嗎？每週至少一次使用者選定的 next step；所選 project 至少一次具體成果確認不按任務總數、字數、工時、薪資或 positive mood 計分；自報／來源 receipt 分列
是否理解因果？訪談能指出物件來源與下一步；來源卡打開率僅輔助不能用點擊率代替理解度
是否願意回來？D1／D7／D30 exact-day Garden meaningful session retention；W1／W4 任一天回訪；同報 OS meaningful-action retention以首次可玩 Garden 為 cohort 起點，固定分母；D30 需真的觀察足月，不能提前外推
有沒有提醒負擔？每 eligible user-week 邀請數、dismiss／關閉／snooze、對通知打擾的自述不把高開啟率視為成功，可能只是使用者想消除提示
有沒有產生壓力或刷分？新建即完成占比、split／undo 異常、機會未使用、使用者表示為拿獎而做無意義行動異常是研究線索，不自動懲罰；合法小任務可能非常重要
跨裝置是否可靠？save 成功率、retry／conflict、重複 grant、schema mismatch、崩潰／context loss、frame time 分位數依裝置／網路／模組可用性分組；沒有事件不能當作零問題

最小新增 telemetry：garden_entered、layout_previewed（採樣，不逐格記錄）、world_command_committed、observation_completed、opportunity_issued/used、source_unavailable、invitation_shown/dismissed、session_finished、feedback_answered。持久 grant 的交易表才是獎勵分析真相，telemetry 丟失不補發獎。採最小模組類別／匿名化 cohort／版本，不收內容全文、原始滑鼠軌跡或音訊；設定保留期限與可停用研究量測。

驗證順序與取捨標準

先找 6–8 位有不同 OS 使用習慣的人做定性試玩，包含只用 Tasks、偏反思、忙碌／常中斷、手機為主者。每人先給 3 分鐘無生活獎勵的配置機會；觀察是否理解、做選擇、主動嘗試第二種配置。再給一個生活來源機會，看是否清楚世界為何改變。這是可用性／動機線索，不是小樣本留存顯著性。

首輪可調的放行條件：至少 6/8 能在不口頭教學下完成第一個有效配置；至少 6/8 說清楚來源與成果；至少 5/8 主動想試另一種配置。若不達標，先改控制／回饋／空間題，不先加新魚。若有人把提醒理解為不回來會害死魚，先修文案與狀態。

接著做自願小規模 beta，收至少兩週過程資料；滿 30 日才看 D30。之後才按 account 隨機分配 V2／V3 的對照實驗，預先訂 primary metric、最小可接受差異、樣本量、觀察窗與停止規則；依實際 baseline 計算 power，現在不捏造人數或 uplift。分層看新／舊玩家、模組使用、裝置能力，並單列同意參加者的 selection bias。

對照實驗採 intention-to-treat：分母保留所有被分到該版本的合資格帳戶，不能只算主動開啟魚塘的人；前述 Garden 啟用者北極星另作產品診斷指標。首個實驗只比較核心玩法，提醒兩組均關閉或沿用相同設定，避免把通知增加造成的回訪誤認成遊戲更好玩。核心通過後，再對已同意提醒的帳戶獨立測試內容邀請；同步觀察提醒負擔與 OS 行動，不以通知點擊率作唯一主要指標。

如果回訪升但「有意義的自選行動」下降、玩家感到更被提醒打擾，不算成功。如果享受度高、生活連結理解低，先改來源與建設機會的關係。若使用者只需要每週兩三次，卻更喜歡 OS 且有實質推進，不為追求 DAU 強迫改成每日簽到。

13. 現在應作的開發決定

批准方向時，最值得先選的是 P0＋P1：三種動物、一個魚塘、四類物件、四種可靠生活入口、一套持久且可解釋的授權與世界 command。這是足以驗證「遊玩本身有趣」與「生活留下痕跡」的最小完整範圍。

首輪原型的關鍵不是魚有幾十種，而是玩家能否因放置方式不同看到不同的水路／行為，失敗後願意自己改一次。若這個行為成立，後續的育成、濕地與森林才有根基。
