# 活水魚塘：首輪試玩執行包

狀態：待真實參與者測試。沒有招募、訊息發送、訪談結果或留存數據。沿用方案的 P0／P1 驗收，不把自動測試成功當成玩家享受。

## 對象與安排

邀請 6–8 位自願參與者，包含只用 Tasks 的新手、使用 Habits／Gratitude 的既有用戶，以及願意用純 starter 遊玩的用戶。先做每人約 20 分鐘的個別試玩；依取得的同意記錄操作時間和自願意見。不要錄製私人日記／感謝內容，測試管理表用匿名參與者代號。模組連接可拒絕，退出沒有後果。

每人使用自己的主要裝置；其中至少各有 iOS Safari、Android Chrome、桌面鍵盤。平板另跑觸控及橫直向。模擬器只可補查版面，不替代這些實機。記錄瀏覽器版本、裝置型號、畫質檔位、繪製像素及音量設定；不可由價格推定效能。

## 主持順序與中立提示

1. 「請走進花園，看看這裡可以做甚麼。」前 60 秒不解釋規則，記下首次有效操作、入口是否找得到、誤點位置。
2. 「試著佈置一個你喜歡的水邊，讓魚沿你選的路線走。」只在玩家卡住 90 秒後提供 UI 已有的提示，標記是否需要協助；不代操作、不先示範標準解法。
3. 「如果你想為這個地方添一件东西，請選一項今天對你有用的小事。也可以選休息，或不連接生活資料。」測量從自主選擇、原模組保存，到建造並讀回的時間。這不要求當場完成不合理的工作，原本不适合的小事可以改選。
4. 回到已建成的世界，請玩家用自己的話說明物件從哪裡來。可記是否正確歸因；不可替其人生選擇打價值分數。
5. 「你可以再玩一會，也可以現在結束。」接下來三分鐘沒有新生活獎勵、不提示第二解法。觀察是否主動改配置、重走不同路線或選擇結束。結束是有效意見，不記為個人失敗。
6. 顯示實際 Buddy 邀請設定，讓玩家自行決定是否啟用。問「這類訊息甚麼時候對你有用？甚麼時候會打擾？」不以 opt-in 率越高越好。

奇數參與者先自行佈置；偶數可先觀察 starter 魚路，再佈置。這只平衡學習順序，不是足以估計因果留存的 A/B 實驗。

結束後自撰三題，1–5 分並可拒答：「操作是否容易掌握？」「你喜歡剛才的遊玩嗎？」「你覺得可以按自己的意願結束嗎？」另問「你最想再做哪個操作？為甚麼？」這些是產品訪談題，沒有聲稱使用已驗證量表。

## 推進規則

先報逐位結果与卡點，不把小樣本分數包裝為市場留存。若多數玩家必須由主持人解釋才能理解水道／物件來源，優先改入口與回饋。如果能完成但沒有一人願意在無新獎勵時嘗試其他配置，先改善玩法選擇，不加更多幣或提醒。通過後才安排兩週 beta，P2 的開發決定需包含實際自主遊玩證據。

實機十分鐘檢查要包含：佈置、移動物件、旋轉石頭、引導與觀察、暫停／恢復、橫直向、離線重試、全螢幕／沉浸式 fallback、降低畫質、減少動態、音樂／音效獨立靜音及退出清理。記錄持續幀時間、發熱與觸控誤觸，不只留靜態截圖。

## Beta 與 D30

後續依主方案第 12 節追蹤 meaningful action、source attribution、project progress、自主 replay、提醒負擔及 D1/D7/D30；event schema 與使用者資料告知需在真實採集前落實。現在的 `garden_world_events` 只足以解釋世界事實，不等於已有完整 analytics pipeline。沒有 event 或 baseline 的指標保持「未量測」，不可用估計數補值。
